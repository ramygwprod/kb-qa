The flow

One batch, four roles, one boundary

A batch is a fixed, named list of URLs on one surface. It moves left to right through four roles. The only thing that crosses the boundary is a human carrying a report — there is no automated path from a verdict back to the agent that produced the rows.

Why the split holds

Separation by capability, not by instruction

A markdown file that says delegate to the fetcher is a request, and a request is skipped under pressure with nothing noticing. Each role is instead defined by the tools its session does not have.

kbqa-collect

TaskAgentReadWebFetchWriteBash

Orchestrates and nothing else. It cannot fetch a page, create a file, or run a command — so delegation is the only available action, not the recommended one.

fetcher

WebFetchWriteReadBash

Holds the network. Writes the capture and the denominator, computes the capture's hash, and returns a receipt. Never interprets, never emits a row.

row-writer

ReadWriteBashWebFetch

Holds no network tool, so the capture on disk is its only possible source. Invention is not forbidden here — it is unreachable.

kbqa-check

BashReadWriteEdit

Runs the gates and reads verdicts. Cannot modify a gate, a capture, or a row — so it cannot make a failing batch pass.

The hash travels in the receipt rather than being recomputed by the row-writer. A hash produced and verified on the same side proves only that a file hashes to its own hash.

The gates

Seven checks, each answering one question

GateAsksOn failure
G0May we fetch this host at all?Exit 2 — declined. Stop. No retry, no alternate fetcher, no rendering service
G1Did this capture exist, unmodified, before these rows?Missing capture, hash mismatch, unbalanced markers, undeclared pages
G2Do the rows satisfy the contract?Schema violation, duplicate id, zero rows, parser disagreement
G3Is each quote verbatim on the page it cites?Quote absent, quote from the wrong page, url not in capture
G4Is every index item covered, or explicitly stopped?Uncovered item; a stop-condition with no stated observation
G5Do any rows look like bundled terms?Advisory only — always exits 0
G6Do verdicts, manifests and the merged tree agree?Stale verdict, unchecked batch, role collapse, manifest mismatch

Exit 2 means declined and nothing else. A usage error exits 1, never 2 — a typo must never be readable as a permission decision.

Routing

A finding says what may legitimately change

A maker handed “G3 failed, 14 rows” will edit fourteen quotes until the gate goes green — which is the defect this pipeline exists to catch, not a repair of it. So every finding carries a class, and the class names its destination.

Corpus state

Three tiers, and the one that is not a tier

A corpus is in good order when each batch sits in the tier it ought to, not when every batch is verifiable. The failure state is not knowing which is which.

verifiable

The capture splits into page blocks and every quote is checkable. 6 batches · 2,034 rows at last sweep.

unassessable-no-page-markers

The text was stored but has no page boundaries, so no page owns any of it. Not the same as ungrounded — recoverable by re-fetch. 3 batches · 424 rows.

unverifiable-no-capture

Page text was never stored. No gate can ever ground these; only re-collection can. 174 batches · 10,335 rows — the bulk of the backlog.

not-a-batch

Matched the staging filename pattern while declaring no batch frontmatter and holding no rows — a note, a ruling, a session log. Excluded from every figure and named, because a file that vanishes from a total is indistinguishable from one that was never there.

Honest limits

What the machinery does not reach

G3 does not check that a quote supports its claim

It verifies the quote is real and on the cited page. A row whose description says far more than its quote warrants passes every gate. This is the largest gap and the one quote-shopping exploits.

The capture is what the fetch tool returned

Not necessarily what the server sent. A tool that converts or summarises yields quotes that match the capture while differing from what a reader sees on the page. Verify once per fetch mechanism, by hand.

Coverage is measured against the denominator we captured

If the index itself was selective, nothing notices. This is why the fetcher captures the vendor's own list before scope is decided.

Gold has no producer

G6 validates feature-tree.md's declared proof count, but nothing in the pipeline writes that file. Hand-written, the count is self-attested and the check is vacuous.

Enforcement stops at level 3½

Gates run from a pinned tag on infrastructure the collector cannot reach — but a private repo on a free plan cannot require a passing status check. Tampering is visible and inconvenient, not impossible. That works only while a human reads the verdicts.
